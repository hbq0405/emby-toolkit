# 处理流程

新版所有资源尽量汇入同一条核心工作流。不同来源只负责把资源或需求送进来，后面的识别、整理、元数据和媒体库刷新使用统一规则。

## 1. 资源进入

资源可以来自：

- 本地媒体目录和媒体实时监控。
- 115 待整理目录、115 分享入库和共享池。
- re0、Telegram 频道监听和 Telegram Bot 手动转存。
- MoviePilot 下载/转移事件和订阅需求。

## 2. 识别和规划

ETKN 先根据文件名、父目录、媒体类型、外部身份和配置规则判断影视身份，再规划目标目录、命名、版本和入库方式。识别不确定时，任务会保留诊断信息，便于从整理记录人工纠错。

## 3. 核心入库

核心入库按任务项执行：

1. 读取或准备文件、分享或直链资源。
2. 识别电影、剧集、季度和分集。
3. 应用分类、映射、命名、词表和洗版规则。
4. 处理 STRM、字幕、图片、元数据、媒体信息和片头片尾信息。
5. 刷新内置媒体服务并校验媒体身份。
6. 写入任务历史和整理记录，并触发后续订阅、通知或共享动作。

## 4. 事件入口

内置媒体服务事件：

```text
POST /api/emby/events
POST /api/media-server/events
```

MoviePilot 事件：

```text
POST /webhook
```

前者服务于 ETKN 内置媒体服务和兼容客户端的元数据、图片、刷新、用户状态等事件；后者服务于 MoviePilot 的订阅和转移协作。两者不会合并成旧版的 `/webhook/emby` 入口。

## 5. 任务链和失败处理

任务中心保存根任务、后代任务、阶段日志和失败原因。某个分集失败时，通常只影响对应任务项；需要重试、重组或纠错时，从根任务或整理记录进入，避免重复创建同一批资源。
