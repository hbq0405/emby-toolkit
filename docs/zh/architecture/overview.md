# 架构总览

ETKvNext 是一套由管理控制台、任务工作流、媒体处理、内置媒体服务和外部资源连接组成的系统。用户看到的是一条连续流程：找到资源，完成识别和整理，写入媒体库，再通过 ETKN 的媒体服务浏览和播放。

## 主要组成

- **管理控制台与 API**：提供登录、配置、任务、媒体管理、用户和权限操作。
- **核心入库工作流**：统一处理本地媒体、115 资源、分享入库、虚拟入库和 MoviePilot 转移文件。
- **资源与订阅中心**：连接 115、共享池、re0、Telegram 频道和 MoviePilot，负责发现资源与生成需求。
- **任务中心**：把一个操作拆成根任务、处理项和后续任务，保存状态、日志、失败原因和重试结果。
- **内置媒体服务**：在 `8097` 提供兼容 Emby/Jellyfin 的媒体库、详情、图片和播放接口。
- **PostgreSQL 数据库**：保存配置、媒体身份、版本、任务、整理记录、用户、播放记录和授权状态。

## 两个服务端口

- `5257`：管理页面和管理 API。
- `8097`：内置媒体服务和虚拟媒体库。

这两个服务都属于 ETKN。新版不要求额外安装外部 Emby 或 ETK MediaInfo Bridge 才能完成核心流程。

## 处理链路

1. 资源来自本地目录、115、分享链接、共享池、re0、Telegram 或 MoviePilot。
2. ETKN 识别电影、剧集、季度和分集，并按配置生成整理计划。
3. 核心入库工作流执行移动/映射、命名、STRM、字幕、图片、元数据和媒体信息处理。
4. 任务完成后刷新内置媒体服务，并把结果写入整理记录。
5. 订阅、追剧、洗版、共享池和通知等后续动作根据任务结果继续执行。

## 事件和任务

内置媒体服务事件通过 `/api/emby/events` 或 `/api/media-server/events` 排队处理；MoviePilot 外部事件使用 `/webhook`。事件入口只负责接收和排队，实际动作在任务中心中执行，便于查看完整后续链路。
