# 常见问题与故障排查

先判断问题发生在连接、入库还是播放，再到对应记录里查。排查同一资源时，记下影片、版本、客户端和发生时间。

## 网页或后台打不开

1. 确认 `etkn` 与数据库容器正在运行，查看迁移与启动日志。
2. 使用实际媒体端口访问，新部署示例是 `http://服务器IP:8097/web/`。
3. 管理与个人中心是同一端口的 `/profile`；`5257` 是容器内 API 上游，不需要重新公开。
4. 检查 `http://服务器IP:实际端口/api/health`，再核对映射、反向代理与防火墙。

已有后台保存端口优先于环境变量。只改 Compose 环境变量而没核对保存值，可能导致端口不一致。

## 白屏或更新后页面还是旧的

先强制刷新并确认地址正确。仍异常时查看浏览器网络错误，确认入口 JS 返回 JavaScript 而不是 HTML，静态目录可读。反向代理不要长期缓存入口 HTML。

## 本地目录选不到，或者音乐库是空的

后台选择的是容器路径。先检查宿主机目录是否已映射、容器用户能否读取，再选择合适内容类型刷新。音乐还需要可识别音频标签；家庭视频不必强行套用影视识别。

## 任务成功，但没有入库

“转存成功”“生成 STRM”只代表阶段完成。打开任务中心的根任务，检查后续整理、元数据、媒体信息和发布；到整理记录核对最终版本。

识别、探测或质量门禁失败可能只影响当前候选。不要因为同批其他分集成功，就认为整季都已完成。

## 影片有了，用户却看不到

先检查媒体库来源、刷新结果和用户模板的媒体库/路径/分级权限。占位项没有可播放版本，出现卡片也不代表视频已经获取成功。

分组展示需要客户端支持；更新客户端后再核对。分组不额外增加额度，组内子库仍分别计数。

## 播放失败或持续缓冲

1. 确认同一影片、同一版本、同一音轨，记录实际客户端。
2. 在 **正在播放** 查看来源是本地、直链还是缓存，是否启用了音频/视频转码。
3. 直链播放检查 115/分享有效性、个人播放账号要求和客户端能否访问上游。
4. 缓存播放检查内网识别、磁盘空间与权限、上游下载是否继续；未缓存的跳转位置可能要等待。
5. 官方 Web/TV 需要适配时，检查 **自动转码配置**、云端原片缓存和硬件状态。
6. 切换较低质量或其他可用版本，再检查声音、画面和字幕。

公网、未知地址或缓存关闭时，继续原有直链策略。不要把浏览器格式不兼容直接当成网盘限速，也不要把一次 `302` 解析日志当成最终播放来源。

详见 [缓存与转码](/zh/guide/playback-cache)。

## 为什么缓存没有自动预取下一集

当前播放需过半，且当前集已完整缓存，才会预取下一集。当前集仍在下载时优先完成当前集；停止后会暂停并保留断点，重启不会自动续跑明确暂停的任务。

## 没有声音或多声道听不到

先换音轨并确认电视/音响输出设置。浏览器不一定能直接解码 DTS、TrueHD 或所选多声道；允许转码后可能只适配音频而保留原视频。播放器显示原画不等于每条音轨都原样直解。

## 中文字幕或 AI 翻译没有出现

先选对字幕，检查个人优先级。AI 翻译需要可读取文本，不会从 PGS/SUP 图片或没有字幕的音频里自动生成译文；再检查 AI 连接、额度、源字幕读取和目录写入权限。

第三方客户端没有官方实时翻译界面。完整外挂与实时译文的使用方式见 [字幕与翻译](/zh/guide/subtitles)。

## 弹幕在基础设置里找不到，或者只部分集数有

入口现在是 **增强功能 → 弹幕**。后台服务与播放器显示开关都要开启；自定义来源还要填写正确的兼容 API 根路径。

匹配依赖片名和季集，某集有结果不代表整季都有；首次抓取可能等待更久。未找到或失败不会阻断视频，见 [弹幕](/zh/guide/danmaku)。

## TV 找不到服务器或无法更新

自动发现受网络影响，先手动填写实际媒体地址并确认电视可达。更新需要完整下载、校验和系统安装确认；系统阻止安装时，查看设备上对当前来源的安装设置。

## Telegram Bot 正常，频道却没反应

Bot 轮询与频道监听是两套配置。分别检查 Token/接收目标与 Telegram 用户会话授权、白名单、监听状态，不要用 Bot 正常推断频道已经登录。

## 共享资源没有继续整理

检查资源获取独立任务、后续整理任务、115 目录状态与任务日志。推送是否消费、资源是否实际获取、是否最终入库是不同环节。MoviePilot 报告完成也不代表 ETKN 后续已完成。

## 识别错误或洗版后有残留

先在整理记录确认文件身份、纠错/重组与清理事件。不要通过反复整批提交、强制重处理或直接改数据库来替代目标明确的修正。清理前核对版本、路径及是否包含云端文件。

## 文档为什么还在旧仓库地址

新版源码仓库是私有仓库，本站继续借用旧版公开仓库发布用户文档。文档主体面向 ETKN；公开文档地址不代表新版程序仍使用旧版实现。

## 反馈时提供什么

提供影片与版本、客户端、时间、期望与实际结果，以及对应根任务的脱敏日志或播放记录。不要发送 Cookie、密码、Token、带认证的直链或数据库备份。
