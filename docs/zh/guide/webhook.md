# 事件与 Webhook

新版把事件分成两类：ETKN 内置媒体服务事件，以及 MoviePilot 外部事件。它们的入口和作用不同。

## 内置媒体服务事件

内置媒体服务兼容 Emby/Jellyfin 客户端。媒体服务或兼容客户端发生元数据、图片、评分、用户策略、合集变更或刷新请求时，事件会进入 ETKN 的事件任务链。

兼容入口：

```text
POST /api/emby/events
POST /api/media-server/events
```

事件通常只负责排队，真正处理在任务中心执行。刷新请求可能触发元数据刷新、图片替换、缺失信息补齐或片头片尾处理；播放状态则会进入播放记录和统计。

新版不依赖 ETK MediaInfo Bridge 插件才能完成核心流程。标题、简介、图片、媒体信息和事件处理由 ETKN 自己的服务与任务完成。

## MoviePilot Webhook

MoviePilot 使用独立入口：

```text
POST /webhook
```

它用于接收订阅变化、下载状态和转移完成事件。事件进入资源获取或订阅助手后，ETKN 继续执行识别、整理、元数据处理和入库。MoviePilot 报告“完成”不代表媒体已经出现在 ETKN 媒体库中。

## 排查事件链

1. 先在任务中心按时间找到根任务。
2. 打开任务详情，确认事件类型、失败阶段和后续任务号。
3. 资源已转存但没有整理时，检查是否生成了后续整理任务，以及 115 目录是否已经同步完成。
4. 媒体已整理但客户端看不到时，检查 `8097` 是否可访问、媒体库刷新任务是否成功，以及客户端使用的地址是否是代理后的地址。

不要再按旧版 `/webhook/emby` 或 Bridge 插件状态判断新版主流程是否正常。
