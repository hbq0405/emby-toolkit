# 内网缓存与转码

缓存让服务器保留播放中的原片；转码用来适配设备或浏览器。两者分别配置，开启缓存不会自动开启转码。

## 先选适合的方式

| 场景 | 播放方式 |
| --- | --- |
| 本地实体视频 | 由服务器提供本地文件 |
| 远程资源，自动缓存关闭 | 解析直链后由客户端播放，通常显示 `302` |
| 服务端识别为内网，且已开启自动缓存 | 服务器边下载边提供缓存数据 |
| 公网或无法确认客户端地址 | 继续使用原有直链方式，不自动套用内网缓存 |
| 官方客户端需要适配格式或画质 | 满足服务端开关、网络及素材条件时使用转码 |

第三方兼容客户端可以使用内网自动缓存；官方 Web/TV 的转码能力不能据此推广到所有第三方播放器。

## 开启内网自动缓存

管理员进入 **基础设置 → 媒体库**：

1. 开启 **内网自动缓存**，默认关闭。
2. 选择 **播放缓存目录**，默认是 `/config/playback-cache`。
3. 设置 **播放缓存上限（GB）**，默认 `50` GB。
4. 保存，用一部影片检查是否真正进入缓存播放。

自定义目录必须在容器内可写，并映射到有足够空间的宿主机磁盘。原片、未完成下载和转码产物共用容量；另选目录不会自动搬运旧文件。

## 缓存什么时候保留或回收

- 同一版本共用下载；当前影片可以边下边播，不需要等整片完成。
- 最后一个观看者停止后暂停下载，保留未完成文件和断点；再次播放时继续。
- 重启不会自动恢复明确暂停的下载，后续播放才会触发续传。
- 不按固定天数过期，也不在播完后立即删除。
- 超过容量时回收较早且不活跃的缓存，正在播放或下载的文件受保护。
- 下一集预取同时要求 **当前播放进度过半、当前集完整缓存**；当前集未完成时继续优先处理当前集。

跳到未缓存位置可能需要重新等待上游数据。缓存降低重复读取，不保证首次起播、任意跳转都没有等待。

## 自动转码配置

在 **基础设置 → 媒体库 → 自动转码配置** 中启用，按 NAS 性能设置默认质量、是否保留原始帧率、HDR 色调映射等选项；系统运维中可设置最大并发转码数。

官方 Web/TV 可在解码受阻或选择较低质量时请求适配。云端原片需要已开启的缓存提供输入；已有本地实体视频不需要先从云端下载。

有些场景只需要转换音频或封装，视频仍可复制；另一些场景需要重新编码视频。实际路径以播放中心显示和当前设备能力为准。

### 硬件与 HDR

硬件加速需要宿主机具备支持的 GPU、驱动和容器设备访问权限。Intel 设备常见映射为 `/dev/dri:/dev/dri`；只有宿主机存在对应设备时才添加。没有可用硬件时的表现取决于配置与 CPU 性能。

HDR 保留、HDR 转 SDR 与杜比视界是不同能力。色彩效果取决于片源、编码路径、屏幕与客户端，不能把某个 HDR 样本成功视为全部格式都兼容。

## 怎么判断是否生效

打开 **正在播放**，查看对应会话的来源与转码信息；实际缓存会话应按缓存来源观察。`302`、缓存、视频编码与音频编码分别描述不同环节，不能把“转码”理解成“整片已缓存”。

通过反向代理访问时，客户端地址是否被识别为内网也会影响行为。不要通过伪造请求头强行启用，先核对代理与实际网络。
