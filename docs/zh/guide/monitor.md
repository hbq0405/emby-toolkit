# 媒体实时监控

媒体实时监控会观察配置的本地媒体目录。发现新文件或文件变化后，ETKN 会把它交给核心入库流程，完成识别、元数据、媒体信息、整理和内置媒体服务刷新。

## 监控和监控上传的区别

- **媒体实时监控**：观察媒体库目录，发现已经存在于本地的媒体变化。
- **监控上传**：观察本地待上传目录，把文件上传或同步到 115，完成后可按配置删除本地源文件。

两者可以分别开关和配置，不要把上传目录误当成媒体库目录。

## 推荐流程

1. 在媒体库设置中配置媒体库根目录和需要监听的本地路径。
2. 排除下载中的临时目录、缓存目录和不完整文件目录。
3. 保存后观察任务中心是否出现监控触发的核心入库任务。
4. 入库完成后，从整理记录查看最终识别名称、入库方式和失败原因。

ETKN 内置媒体服务由 ETKN 自己刷新，不需要安装外部 Bridge 插件，也不需要为新版关闭某个外部 Emby 的媒体库监听。

## 注意事项

- 监控路径应是容器内可以读取的路径，并与 Compose 挂载保持一致。
- 文件正在复制时可能被提前发现；建议让下载程序先写入临时目录，完成后再移动到监控目录。
- 监控事件会进入任务队列，短时间批量复制时不要重复手动提交相同媒体。
