# 115 网盘

115 是 ETKN 最常用的存储和资源处理来源。新版同时支持 OpenAPI 和 Cookie 两类接口，并把目录选择、整理、分享入库和播放拆成可追踪的任务。

## 授权方式

进入“服务授权”：

- **OpenAPI**：网页登录或自定义 AppID 扫码授权，适合目录和常规接口操作。
- **Cookie**：扫码或手动录入，可选择网页、移动端、桌面端等客户端类型。

授权后在“设置中心 -> 115 网盘”检查接口状态、请求间隔和并发配置。播放池中的小号需要单独配置，不能把主号凭据随意复制到每个用户的个人配置。

## 目录

至少配置：

- **待整理目录**：资源转存、离线下载或云资源获取后的入口。
- **网盘媒体库根目录**：最终生成 STRM、字幕或媒体文件的位置。
- **未识别目录**：无法确认影视身份的文件暂存位置，方便人工处理。
- **图片仓库**：留空时使用 `/config/media_images`。

目录都应通过浏览器选择。手动填写时要确认是容器内可访问的路径或真实 115 目录，而不是宿主机临时路径。

## 整理主流程

1. 扫描待整理目录。
2. 按电影、剧集、季度和分集归组。
3. 用文件名、父目录、TMDb 身份和资源上下文进行识别。
4. 按分类、命名、映射、词表和洗版规则计算目标。
5. 移动或上传资源，生成 STRM、字幕及必要的图片/元数据文件。
6. 读取或补齐媒体信息，完成刮削、翻译和媒体库发布。
7. 把每个文件的结果写入整理记录，并把阶段日志留在任务中心。

剧集通常以整季作为根任务，分集在任务内部处理。资源获取失败、识别失败、质检拦截和后续发布失败会分别显示，不等于“生成了 STRM 就完成”。

## 分享入库

增强功能里的“分享入库”可以直接粘贴 115 分享链接，每行一个，也可以带提取码。它会检查来源文件并把可识别文件接入整理链，不要求先把分享转存到自己的目录。

- 链接检查只更新有效性，不会因为一次网络错误就删除来源。
- 开启“自动删除失效链接”后，定时维护才会清理明确失效的来源及关联本地版本。
- 删除分享来源会进入联动删除流程；其他来源仍在使用的版本会保留。
- 分享入库的媒体默认不参与共享资源登记，避免把临时来源重复发布到共享池。

## 播放

ETKN 内置媒体服务负责生成客户端可用的媒体响应：

- 本地资源由 ETKN 直接提供。
- 115、分享和共享池等非本地资源解析直链后返回 `302`，由客户端直接访问源站。
- 不会因为客户端 UA、Range 或 ffmpeg 请求就自动把远程视频改成 ETKN 长时间中转。
- 远程播放需要配置客户端可访问的 ETKN 地址，以及可用的播放账号/Cookie 策略。

## 资源不足时怎么查

先看任务中心的根任务和后续任务，再看整理记录：

- 没有根任务：检查资源来源是否真的提交成功。
- 根任务存在但未识别：看识别阶段的文件名、目录和 TMDb 诊断。
- 整理成功但媒体库没有：看媒体库发布和媒体服务日志。
- 播放失败：看播放中心的播放事件，再检查直链解析、账号限制和客户端访问地址。
